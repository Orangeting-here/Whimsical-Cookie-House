# 更新指南 · miniprogram-1 → 单文件 HTML

> 本文档是「后续替换更新」的增量规范：小程序源码更新后，如何把改动
> 同步进 `index.html`，以及每轮更新必做的检查清单。作者：轻枫万悦。

## 1. 目录与产物约定

```
项目根目录
├── src/miniprogram-1/        # 小程序源码（更新从这里改起）
├── runtime/                  # 浏览器运行时（vfs/core/ui/wx-api/ocr-adapter/videodec-adapter）
├── build/                    # 构建脚本（build.js 为入口；smoke.js/interact.js 为调试冒烟，非交付物）
├── dist/index.html           # 唯一交付产物（GitHub 仓库放这个）
├── 移植说明.md               # 技术方案与功能对照
└── 更新指南.md               # 本文档
```

**铁律：只改 `src/`，永远不手改 `dist/index.html`。** 产物由构建生成，
手改会在下次构建时被覆盖。

## 2. 标准更新流程（改动业务代码后）

```bash
# 1. 在 src/miniprogram-1/ 里改代码（WXML/JS/WXSS/资源）

# 2. 重新构建
node build/build.js

# 3. 三类必做检查（见 §4/§5/§6）
#    a. 页面冒烟：node build/smoke.js        （33 页导航全绿）
#    b. 交互冒烟：node build/interact.js     （关键交互全 CLICKED）
#    c. 脱敏扫描：见 §6 命令

# 4. 浏览器里人工过一遍改动的页面
```

> 冒烟脚本依赖 headless Chromium（`<自备 Chromium 路径>`）与
> `<ws 依赖目录>`；换机器后需自行安装 Chromium 与 ws 依赖。

## 3. 新增页面 / 新增模块

1. 按小程序规范新建 `modules/<key>/pages/...`（WXML/WXSS/JS/json）。
2. 在 `app.json` 的 `subPackages` 注册分包；若要在首页出现卡片，
   在 `config.js` 的 `modules` 数组追加一条记录。
3. 重跑 `node build/build.js`（构建自动扫描 app.json 全量页面，无需改构建脚本）。
4. 跑 §2 的三类检查。

### 转换工作台（pages/workbench + common/convert-catalog.js）

- 数据源只有一处：`common/convert-catalog.js` 的 `CATEGORIES`，**只分三大类**（`image` 图片 / `doc` 文档 / `zip` 压缩包）。
  「文档」内部用 `groups` 再分小节（`pdf / word / sheet / text / ppt`，含小节名与 op 列表）。
  加一条转换 = 在对应类的某个 `group.ops` 里追加 `{ id, label, from, out, tier, entry, query, note }`；
  卡片点击用 `data-gi`（第几个小节）/ `data-oi`（小节内第几条）定位，不要再用扁平下标。
  `query` 会被拼成 `?target=png` / `?tab=img2pdf` 带进模块。新增子组记得给 `groups` 起名，右栏会渲染 `.op-group-title` 小标题。
- 类型识别：`detectGroup(ext)` 返回 `{cat, group}`，拖入文件的提示会拼成「属于文档 · PDF」。
- 只收录真实能跑通的转换；做不到的（WebP 编码、XLSX 解析）写 `disabled: true`，点了只提示原因。
- 模块侧预选：`imgconvert` 读 `options.target` 直接设 `targetFmt`；`pdfconvert` 读 `options.tab`；
  `pdftext / tableconv / mdconv / docconvert` 读 `options.target` 存 `wbTarget`，用于高亮对应导出按钮。
  **新增模块要支持预选，就在 onLoad 里加这几行，否则点卡片进去还是默认格式。**
- 首页入口：列表视图在「文件转换」组首位插一张 `wb-card`（`_buildModuleGroups` 里注入，`fidx` 不参与排序）；
  宫格视图另有 `.wb-banner` 横幅，都在 `home.wxml`。
- 收编：已被工作台收录的模块在 `config.js` 标 `hideHome: true`，首页渲染层（`_visibleList`）过滤掉，
  不再单独出卡；`_modules` 仍保留全量供排序 / 状态 / 搜索兜底。未收录的模块（如 OCR）不要打这个标记。

### PPT 模块（modules/pptx）

- 页面 `modules/pptx/pages/index/index`，两 tab：`media`（导出 ppt/media 图片）/ `slides`（每页转图 + 讲义）。
- 解析器 `utils/pptx.js`（`parsePptx(bytes)` → `{size, slides, media, warns}`）：PPTX 当 zip 读，
  页序取 `ppt/presentation.xml` 的 `sldIdLst` → `slides/_rels`，图形按 `spTree` 顺序遍历。
  **注意 `zip-tool` 给的条目是 `Uint8Array`，必须 `fromUtf8` 解码后再解析，直接 `String()` 会得到数字串。**
- 重绘器 `utils/render.js`（`paintSlide` / `paintHandout`）：EMU→px 按目标宽度等比换算；
  只画背景纯色 / 图片 / 文本框（段落、字号 `sz%`、粗体、纯色、对齐、垂直锚点）/ 纯色矩形。
- 讲义画布高度必须和 `render.js` 里同一套算法算（`gap = w*0.014`、`cellW = (w-gap*(cols+1))/cols`、
  `cols = count<=2 ? count : 2`），否则 2 页会只占中间一条、上下全白。
- 想扩新能力（渐变、图表、SmartArt、图片裁剪）：改 `pptx.js` 产出形状字段 + `render.js` 落笔两处，别只改一处。

### PDF 加密 / 解密（modules/pdfconvert/utils/pdf-crypto.js）

- 标准安全处理器，纯 JS：MD5 / RC4 / AES-128 自实现。**改密码 PAD 相关代码前先看 `padBytes` 注释**——
  这里曾把 `PW_PAD.subarray(t.length)` 当补位，导致密钥与标准阅读器不一致（自己能在自己这儿解开、别处打不开）。
- 解密要兼容四种 PAD 尝试（标准 Latin-1 / 标准 UTF-8 / 旧版两种），否则本工具历史加密的文件会解不开。
- 加密后务必用外部实现校验一次（`pikepdf` 或 qpdf），只靠内部自检会漏掉这类自洽型 bug。

### 新增页面的 WXML 兼容约束

- 模板里**每个变量必须先声明**（`data`/`properties` 或 wx:for 变量）——
  微信端未声明会静默失效，本构建会直接渲染失败。
- `wx:key` 支持 `"index"` 与字段名；`wx:for` 嵌套变量名会自动映射，无需特殊处理。
- 表达式支持成员访问、三元、逻辑运算；模板字符串拼接请避免在属性值内使用。
- 事件绑定 `bindtap` / `catchtap` / `bindinput` / `bindchange` 等常用事件已覆盖；
  新事件类型需在 `runtime/core.js` 的事件桥接表补充。
- 滚动容器请使用 `scroll-view`（运行时自动加 overflow 滚动），不要依赖页面级滚动写新页面。
- 组件内部方法写在 `methods` 中（运行时已支持），组件内按钮可正常点击；
  不要引用微信专属能力（聊天导入 / getMenuButtonBoundingClientRect 等已在浏览器版降级）。

## 4. 页面冒烟检查（a）

`node build/smoke.js` 输出应满足：
- 33 页（新增后为 33+N）全部导航成功；
- 每页 innerText 含真实业务文本（非空白）；
- 错误汇总为 0。

任一页失败时，用浏览器打开 `dist/index.html`，在对应 hash 路由下看控制台报错定位。

## 5. 交互冒烟检查（b）

`node build/interact.js` 覆盖：首页弹窗、模块卡片跳转、待办添加、
计时器开始、时间计算 tab、阅读器导入、文件池策略、题库导入。
**改到这些页面时必须重跑并确保零错误。**

## 6. 脱敏检查清单（c，每轮更新必做）

```bash
cd 项目根目录
# ① AppID：必须为 0（本工程构建排除 project.config.json，正常应为 0）
grep -c '<你的AppID>' dist/index.html  # 把实际 AppID 填入（本仓库文档与产物一律不含明文）
# ② 本地绝对路径：必须为空
grep -o '/home/user[^"'"'"' )]*' dist/index.html
# ③ 手机号（11 位）：命中仅允许是浮点常数误报，人工确认无真实号码
grep -o '1[35789][0-9]\{9\}' dist/index.html | sort -u
# ④ 其他 AppID/密钥类：检查 appId/secret/token 字段
grep -oi 'appid\|appsecret\|access_token' dist/index.html
```

发现真实敏感信息时，先确认它来自哪个源文件，从 `src/` 删除后再重跑构建。

**更新时最容易踩的坑：** 新增的 js 文件里写了注释含手机号 / 测试账号 /
内网地址，构建会把注释原样打包。改完代码随手跑一遍 §6 的 4 条命令。

## 7. GitHub 发布流程（Orangeting-here / Whimsical-Cookie-House）

1. 推荐目录结构（导航页在根，工具箱挂在子目录）：
   ```
   repo/
     index.html          ← 你的单文件导航页（原样保留）
     .nojekyll           ← 空文件，阻止 Jekyll 重排
     toolbox/
       index.html        ← 本项目产物（dist/index.html）
   ```

2. 开启 GitHub Pages（Settings → Pages → Deploy from a branch → main 根目录）。
3. 发布后访问导航页链接即可；工具箱地址为 `…/Whimsical-Cookie-House/toolbox/`。
   Pages 为 https，OCR 引擎与语言包的 CDN 懒加载条件才成立。
4. **`sw.js` 不能漏传**：缺它只是没有离线能力，页面照常可用；`embed.js` 只在
   导航页需要嵌入时才用到，单独打开 `toolbox/index.html` 不依赖它。
5. 每次更新后按 §2 全流程走一遍再 push。AppID 已从 `project.config.json`
   替换为 `touristappid` 占位；若要把 `src/ build/ runtime/` 也公开，先按 §6
   脱敏清单再扫一遍（`wx[a-f0-9]{16}`、手机号、邮箱、内网 IP、密钥）。
6. `project.private.config.json` 是本地私有工程配置，建议写进 `.gitignore`，不入库。

## 9. 桌面皮肤层（「桌面工作台」设计语言）

两套皮肤是主题系统的第三维度（与 浅/米/深 模式 × 蓝/紫/青 主题色 正交），设计主张：**应用是一张真实工作台**——统一左上光源、真实厚度、材质分级、触感反馈。

- **玻璃工作台**：深墨蓝毛毡桌垫（SVG 噪点纹理 + fixed 紫蓝光斑），卡片为磨砂玻璃（`backdrop-filter: blur(18px)`，光斑真实透底），banner 为彩色玻璃，弹窗深玻璃；
- **软陶工作台**：浅杏软木桌垫（噪点+木纹+四角渐晕），卡片为黏土厚块（顶高光 + 5px 侧面厚度 + 地面投影三件套），面板 1° 内微倾如摆件，模块宫格低饱和糖果染色，按钮有按压下沉；
- **原版（classic）**：不加载任何皮肤规则，保持 1:1 小程序观感。

**机制**：
- 开关 `body[data-skin="glass"|"clay"|"classic"]`，存 `mp_theme_skin`，启动由 boot 代码恢复；运行时切换走 `wx.setBodySkin`（runtime/wx-api.js）；
- 样式全部集中在 `build/skins.css`，构建后注入在所有页面样式之后，选择器带 `body[data-skin]` 前缀压过页面级规则；
- 深/米模式通过 `:has(.page.dark / .page.sepia)` 跟随，`html:has(...)` 兜底整页场景色（关键：`body{height:100%}` 只铺首屏，不铺 html 滚动区会露出灰底）；
- 业务接入 `common/theme.js`（getSkin/setSkin/getSkinList），首页「设置 → 皮肤」三点切换。

**桌面重排（只对两皮肤、≥1024px 生效，classic 与移动端布局不变）**：
- 首页改三列网格：banner 全宽压缩、病程大卡跨 2 行 2 列、待办+使用报告右列竖排、日历单列+鱼缸横跨 2 列、「其他小工具」全宽、模块分组三列、设置卡三列流；
- `--rpx` 放大到 `min(100vw,850px)/750`（桌面字号体系跟随）；
- 隐藏"左右滑动切换"移动端提示；弹窗/底部面板限宽 520/560px；
- 日历格子桌面降高（52px/格），长文案允许换行或省略。

**默认皮肤判定（易踩）**：无本地存储时按设备决定——移动端 → 原版，桌面 → 玻璃；`build/build.js` 的 bootSkin 与 `common/theme.js` 的 defaultSkin 必须同时改，否则会出现"设置面板高亮原版、页面却是玻璃"的错位。

**桌面细节（都在 skins.css 的 ≥1024px 段）**：首页隐藏空导航条并把 `.scrollarea` 的 top 归零（banner 自带标题，48px 深色条只是多余色带）；这条规则按 `.page-host[data-path="pages/home/home"]` 全局选择器写，不挂皮肤前缀，classic / 玻璃 / 软陶三皮肤同享；其他页面保留导航条（返回键要用）但底色透明、标题转亮色；非首页 `.page` 限宽 1000px 居中，避免单列卡片横跨 1440 显得空旷；首页搜索框 430×54、input 40px 高。

**新增皮肤**：theme.js 的 SKINS 表加一项 + skins.css 加同名 `body[data-skin=xxx]` 块；必须同时配深色版本，否则深色模式会露馅。

## 10. 能力矩阵与档位（runtime/capability.js）

一句话：**能力跟着机器长，不跟着代码死**。启动后跑一次极短的基准（2e7 次整数循环 + 32MB 内存填充 + IndexedDB 写速，Worker 内 3 轮取最小值），加上环境探测（origin / secure / Worker / wasm / 核数 / 内存 / 编解码器）算出一个 0~100 的分与三档：`high` 流畅档 / `mid` 标准档 / `low` 轻量档。

- 参数出口只有一处：`plansFor(kind)` → `{ image, pdf, ocr, zip, doc, video }` 的 `conc / chunkMB / maxEdge / maxMB / pagesPerBatch / dpi / batchPerRun`。业务侧一律通过 `common/capability.js` 的 `plan(kind)` 取，不在页面里写死"最多 N 张"。
- 缓存：`localStorage` 按 `VER|origin|cores|memGB|worker|UA尾24` 指纹存，换机器/换浏览器自动失效重测。
- 校准过三次坑：① 阈值过苛把 2 核 4G 判成 1 分；② 单次采样受 CPU 抖动影响（同机 168ms↔92ms，分数跳 1↔75）→ 改 3 轮取 min；③ `pdf.conc/ocr.conc` 硬编码 2 会跟主线程抢核 → 改为受 `cores-1` 约束；④ `new Worker(blobURL)` 构造成功但异步失败 → 若基准回退主线程则置 `env.worker=false`。
- 页面：`pages/capability`（档位 / 核数 / 内存 / 每项能力在本机的档位）+ 首页入口卡。**只展示与解释，不提供"关闭功能"的开关**——弱机只降级，不隐藏。

## 11. 离线缓存（dist/sw.js）

`build.js` 除了 `dist/index.html` 还会产出 `dist/sw.js`，并在 HTML 里注入注册（`file://` 与不支持的环境静默跳过，单文件分发没有 sw.js 时也只是一次失败的 register，不影响使用）。

- 策略：**HTML network-first**（保证改了立刻生效，断网才回落缓存），其余同源静态资源 cache-first + 后台更新，跨源（CDN）一律不接管。
- 缓存名在 `build.js` 的 `swCode` 模板顶部 `CACHE` 常量；**结构 / 静态资源有较大改动后要升版**（如 `whimsical-v1` → `whimsical-v2`），activate 阶段会清掉旧缓存，避免用户吃到旧包。
- 实测：`http://127.0.0.1` 下注册成功、`whimsical-v2` 缓存建立、页面被 SW 接管；模拟断网重载仍能打开。
- 上传 GitHub Pages 时**必须同时传 `index.html` 和 `sw.js`**（同一目录），否则没有离线能力。

## 12. 嵌入单文件导航页（embed/embed.js）

不依赖框架、不改导航页结构、不用 Shadow DOM：把项目以 iframe 形态做成"全屏 App"，自带「← 返回导航页」与「新窗口打开」，Esc 可关，关闭时把 iframe 置 `about:blank` 释放内存。

```html
<script src="./toolbox/embed.js"></script>
<a href="./toolbox/index.html"
   onclick="return WhimsicalMount.open('./toolbox/index.html','日历助手工具箱')">日历助手工具箱</a>
```

- `open()` 返回 `false`，所以 `return` 会拦住默认跳转；**JS 没加载或被拦时，链接照常跳到 index.html**，不会白屏——这是刻意的兜底。
- 嵌入状态由页面内组件自判：`window.parent !== window` 即视为套壳。此时 `navigation-bar` 自动隐藏标题（壳顶栏已给过标题），只留返回键收成一条；嵌入页没有返回 / 首页键时整条导航条收起，避免与壳顶栏叠两层。独立顶层打开时行为不变。
- 内嵌页想主动关闭：`parent.postMessage({type:'wh:embed-close'},'*')`。
- 演示：`embed/demo.html`（三张卡片，点第一张直接打开本项目）。
- 已知取舍：iframe 内是独立文档，父页面无法读到内部 DOM（同源时其实可以，但不要依赖）；两套滚动条各自管理，已通过全局细滚动条统一观感。

## 13. 任务中心（common/tasks.js + pages/tasks）

本地台账，回答"刚跑过什么、花了多久、是不是跑到一半被打断"。

- 只存元信息：`kind / title / count / done / status / startedAt / endedAt / ms / note`，不存文件内容；上限 60 条，超出丢最旧。
- `begin()` 就落库（`status=running`），所以进程被杀/页面崩掉也能在下次看到；读取时把超过 5 分钟仍 `running` 的改判 `interrupted`（"已中断"）。这是它相对"只记成功"的核心价值。
- 已接入：PDF 导出图片、图片转换、图片合并、OCR 识别、PDF 文字提取、表格解析、Markdown 转换、PPT 图片提取 / 每页转图 / 打包、文档转换（文本→Word、文档转换）。其余模块后续按同一模式接（`begin` → `progress` → `finish/fail`）。`kind` 图标配色在 `pages/tasks/tasks.js` 的 `KIND_META` 补。
- 页面三态徽章：已完成（绿）/ 已中断（黄）/ 未完成（红）；页头显示今日完成数；底部可清空（只清台账，不动文件）。
